# 데이터 기반 서비스: 선택 점검

실제 과제가 서비스를 요구할 때만 적용한다. 공통 프로토콜과 파일 소유권은 .probe-kit/AGENTS.md를 따른다.

1. 사용자가 어떤 입력을 주고 어떤 결과로 행동할지 한 동선을 고른다. 데이터 읽기 -> 처리 -> 저장/출력 -> 화면 확인의 최소 흐름을 먼저 완주한다.
2. API/출력 스키마, 상태값, 저장 위치, 실행 명령과 포트의 소유자를 배정한다. S2 처리/저장, S3 화면/입출력, S4 계산처럼 실제 파일 단위로 나눈다.
3. 인증/역할별 접근, 업로드/데이터 선택, DB, Docker는 README가 요구하는 범위만 구현한다. 읽기 권한과 변경 권한이 다르면 화면뿐 아니라 서버에서 확인한다.
4. 입력 검증과 실제 적용을 구분한다. 잘못된 데이터 적용/처리 실패 후 기존 정상 상태가 유지되는지, 데이터 변경 후 이전 결과가 최신처럼 표시되지 않는지 확인한다.
5. 계산 중/성공/불가/시간초과 등 실제 구현 상태를 화면이나 결과에 연결한다. 구현하지 않은 재시도/폴백/동시성 제어가 있다고 문서에 쓰지 않는다.
6. 필수 조건과 개선 목표를 구분한다. 솔버가 필요하면 제한 시간과 반환 상태, 해의 제약 충족 여부를 별도로 검사한다. 단순 기준안과 비교하고 실행 성공을 최적성 보장으로 표현하지 않는다.
7. 최소 흐름, 잘못된 입력, 반복 요청, 변경/재시작 후 상태를 실제 요구에 맞춰 검증한다. HTTP 성공만으로 계산과 상태가 맞다고 판단하지 않는다.
8. 응시자가 내장 Browser에서 직접 확인한다. 서버 바인딩/실행 방법은 실제 환경에 맞추며 자동 브라우저 조작을 사용하지 않는다.
9. 실제 요구된 실행 문서에 재현 명령과 확인한 결과를 적고 제출 파일/출력 형식을 대조한다. 실제로 확인하지 않은 화면이나 배포를 성공이라고 쓰지 않는다.
