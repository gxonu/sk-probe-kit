# 데이터 기반 서비스

Case 2 및 데이터→서비스 복합 과제에 사용한다. 공통 운영은 AGENTS와 TEAM_PLAYBOOK을 따른다.

1. 사용자가 어떤 결정을 하려는지, 역할별 입력/조회/수정/승인 범위와 필수 제출 규격을 확인한다. 로그인, DB와 Docker는 실제 요구에 있을 때 구현하며 존재를 가정하지 않는다.
2. 입력 적용→검증→계산/처리→저장→조회 한 흐름을 먼저 완성한다. S2/S3/S4의 인터페이스와 파일 소유권, 상태 저장 위치, 실패 책임을 S1이 합의한다.
3. 데이터 적용 실패, 계산 중 실패, 반복 요청과 동시 수정에서 기존 결과가 어떻게 되는지 실제 요구와 코드로 확인한다. UI에 성공을 표시하는 시점과 서버의 저장 완료를 구분한다.
4. 요구된 서버 포트와 0.0.0.0 바인딩을 확인하고 응시자가 내장 Browser에서 직접 확인한다. 서버/DB 초기화와 종료는 소유 세션이 담당한다.
5. API 성공 외에 실제 생성/저장/조회와 역할 경계를 검증한다. 빈 입력, 타입/범위 오류와 불가능한 조건은 실제 계약에 맞춰 처리하고 핵심 계산은 독립 검산한다.
6. 실제 요구된 HOW_TO_RUN과 AI_COLLABORATION은 S7이 코드/실행/결정에 맞춰 작성한다. S8에는 입력부터 출력의 모듈 책임, 미구현 경계, 실패 후 상태와 AI 선택 근거를 전달한다.

## 근무, 휴가와 안전 관제 화면일 때

실제 요구에 따라 운영자의 데이터 적용/생성/배정/승인과 구성원의 조회/신청/사건 확인 동선을 구분한다. 일반 사용자용 경로를 통해 다른 사람의 결과가 노출되는지도 확인한다.

- 허용 상태와 전이 권한을 먼저 표로 합의한다. 사건/휴가 상태 이름과 전이를 키트가 임의로 확정하지 않는다.
- 같은 요청 재시도, 재업로드와 두 사용자의 동시 변경에서 중복 차감/배정과 과거 상태 덮어쓰기를 확인한다. 실패 시 이전 유효 결과와 사용자 오류 표시를 검증한다.
- CCTV 화면에는 실제 사건의 상태/담당/갱신 시각과 확인 가능한 근거를 연결한다. 요구되지 않은 실시간 스트리밍이나 모델 서버를 추가하지 않는다.
- S6는 운영자와 구성원 동선, 권한, 불가능한 배정과 실패 복구를 검토하고 사용자가 내장 Browser에서 확인한다.
