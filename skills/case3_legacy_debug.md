# 기존 코드 수정: 선택 점검

공통 프로토콜은 .probe-kit/AGENTS.md를 따른다. 기존 코드를 이해하고 요구된 오류 또는 기능 범위만 바꾼다.

1. README의 실행법, 입력/출력 계약과 관련 파일을 확인한다. 제공된 테스트를 적절한 범위에서 실행해 초기 결과를 보존한다.
2. 실패 입력과 기대 동작을 고정하고 재현한다. 데이터 값/단위/상태 때문에 생긴 문제인지, 구현 오류인지 구분한다.
3. 원인 가설과 최소 수정 범위를 세션별 TASK_SPEC에 적는다. 관련 없는 일괄 포맷/리팩터링은 미룬다.
4. 수정 후 같은 명령과 입력으로 확인하고 관련 회귀를 점검한다. 기대값은 요구와 독립 근거에서 정하며 구현 결과에 맞춰 바꾸지 않는다.
5. API/파일 형식/스키마의 변경이 필요하면 계약 소유자에게 영향을 설명한다. 최초 승인 범위를 바꾸는 경우만 재합의한다.
6. git diff와 실제 실행 결과를 함께 확인한다. 다른 세션의 파일을 restore/reset/clean으로 지우지 않는다. 허용된 로컬 커밋은 필요한 경로만 지정한다.
7. 자기 결과에 원인, 수정 위치, 재현 명령, 수정 전 실패/후 성공과 남은 한계를 적는다. 검증 미실행은 NOT_RUN이다.
