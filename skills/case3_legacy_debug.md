# 기존 코드 오류 수정과 기능 추가

Case 3에 사용한다. 공통 운영은 AGENTS와 TEAM_PLAYBOOK을 따른다.

1. README, 실행 진입점과 작은 파일 목록을 확인하고 기존 API/스키마/함수 계약과 수정 범위를 정한다.
2. `$probe-debug`로 작은 실패 입력과 기대값 근거를 고정한다. 기존 테스트가 이미 실패하면 이번 변경이 만든 실패와 구분한다.
3. 원인 하나를 최소 변경으로 고치고 같은 재현 명령으로 결과를 확인한다. 관련 회귀만 추가하며 무관한 포맷 변경과 구조 개편을 하지 않는다.
4. 변경 전 실패, 변경 후 결과, 실제 실행 명령, 남은 미검증과 호환 한계를 SUB_RESULT에 남긴다. 공통 기록은 S1에 제안한다.
5. S8이 설명할 수 있도록 발생 원인, 왜 그 수정을 택했는지, 다른 대안, 파급 범위와 독립 검증 근거를 연결한다.
