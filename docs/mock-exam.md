# 제출 전 20분의 코드 기반 설명 연습

현재 코드에서 예상 질문을 만들고, 사용자가 먼저 답한 뒤 근거로 피드백한다. 이전 시험의 코드나 대화를 확보할 필요는 없다. 새 과제에서 실제로 선택하고 구현한 내용이 기준이다.

## 역할과 시간

- S7-records가 최신 작업, 결정, 실행 증거와 미검증의 위치를 제공한다.
- S6-review가 핵심 코드도 직접 읽고 질문/피드백을 맡는다. S6가 없으면 S1이 맡는다.
- S1은 개발 과제 제출 마감 또는 예정된 제출 확정 시각에서 약 20분을 거슬러 시작 시각을 CURRENT에 기록한다.
- 실제 운영 안내가 우선한다. 제출 확정 뒤나 실제 후속 서술형 중에는 이 연습을 진행하지 않는다.
- 자동 예약/감시 기능은 없으며 응시자가 시점에 맞춰 [프롬프트](../prompts/mock_exam_5.md)를 입력한다.

| 남은 시간 | 작업 |
|---|---|
| 20~17분 | 핵심 코드/기록 확인, 예상 5문항 생성 |
| 17~10분 | 사용자가 먼저 짧게 답하기 |
| 10~6분 | 코드 근거로 피드백, 설명 보완 |
| 마지막 6분 | 필수 문서, 실행/저장 상태, 제출 점검 |

전체 회차 종료와 개발 과제 제출 마감을 혼동하지 않는다. 이 배분은 축약 연습이며 문항당 5분씩 풀어 보는 전체 시험 재현과 다르다. 시간이 줄면 문답부터 줄인다.

## 질문 작성 방식

[가상 few-shot](mock-examples.md)에서 질문을 구체화하는 방식을 읽는다. 예시 자체를 정답이나 실제 출제 문항으로 쓰지 않는다.

1. P1: 현재 설계/도구 선택의 이유, 대안, 한계.
2. P2: 실제 입력부터 출력까지 흐름, 모듈별 데이터와 검증 책임.
3. P3: 구현/실행 확인/미구현/가정 구분, 제삼자의 재현 방법.
4. P4: 예외, 시간/자원 제한, 반복 입력과 상태/품질.
5. P5: 입력/설정 변경 위험과 독립 검증 계획.

각 질문에 실제 읽은 파일:행 또는 함수 근거를 붙인다. 코드에 없는 캐시, 대체 처리, DB, 최적화 도구를 사용했다고 전제하지 않는다. 이유 기록이 없으면 사용자의 설명을 묻는다. 코드가 존재하는 것과 실행해 성공한 것을 구분한다.

## 근거와 피드백

- README/제출 규격 → 핵심 코드 → 실제 기록의 순서로 필요한 범위만 읽는다.
- 현재 작업 트리를 기준으로 삼는다. Git HEAD가 같아도 미커밋 변경이 다르면 질문의 근거가 달라질 수 있다.
- 코드 기준, 확인 시각, 읽은/읽지 못한 범위를 짧게 표시한다. 문답 뒤 코드가 바뀌면 영향을 받은 설명만 갱신한다.
- 먼저 문제만 제시하고 사용자 답변 뒤 정확한 부분, 빠진 사실, 근거 없는 완료 주장, 반드시 이해할 내용을 짚는다.
- 점수나 합격 가능성을 단정하지 않고 실제 코드와 증거에 맞는 설명을 돕는다.
- 출제 단계는 읽기와 배정된 자기 보고서 작성만 한다. 앱 변경이나 새 무거운 테스트를 동시에 진행하지 않는다.
- 예상 질문과 실행하지 않은 검증은 실제 기출 또는 성공 결과로 기록하지 않는다.

사용자가 5문항 대신 한 문항씩 요청하면 기존 단일 문항 연습 방식으로 진행한다.
