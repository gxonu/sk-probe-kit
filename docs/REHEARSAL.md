# 실전 파이프라인 점검

이 점검은 하네스가 설치부터 기록, 실행, 검증, 인계까지 연결되는지 확인한다.
기존 과제나 개인 파일을 입력받지 않고 새 임시 폴더의 합성 데이터만 사용한다.
실제 AI 세션이나 업무 담당자 응답을 재현했다고 간주하지 않는다.

준비용 저장소 루트에서 실행한다.

```bash
python3 scripts/rehearse.py
```

설치한 과제 안에서도 실행 파일은 존재하지만 실제 응시 시간에는 이 합성 점검을 반복하지 않는다.
실전에서는 [foruser.md](../foruser.md)를 따라 실제 과제의 필수 흐름을 검증한다.

## 점검 순서

| 단계 | 실행하는 것 | 통과 조건 |
|---|---|---|
| 새 폴더 | tempfile로 독립 과제 폴더 생성 | 기존 프로젝트를 대상으로 받지 않음 |
| 설치 미리보기 | install.py --dry-run | .probe-kit이 생성되지 않음 |
| 설치 | 실제 프로젝트 범위 설치 | 기존 README와 입력 보존 |
| 환경 | preflight.py | 파일 구성, 도구 존재와 Codex 버전 확인 |
| 시간 계획 | plan_time.py | 예시 일정의 기능 동결, 제출 및 확정 한계 확인 |
| 담당과 질문 | 합성 조건의 MAIN/BUILD 파일 | 명세와 쓰기 경로, Q-ID와 R-ID 연결 |
| 데이터 요약 | data_scan.py | 전체 4행을 변경 없이 확인 |
| 실패 검출 | 의도적으로 취소 행을 포함한 결과 | 독립된 고정 기대값 검사가 실패 |
| 올바른 실행 | 취소 제외, 빈 값 보류 후 집계 | 합계 30, 집계 2행, 제외 1행, 보류 1행 |
| 결정과 증거 | decision.py와 보고서 | 실제 명령과 검사 결과 연결 |
| 인계 | BUILD 결과와 MAIN의 확인 기록 | 다음 세션이 경로로 읽을 수 있음 |
| 재설치 | 작업 기록 작성 후 다시 설치 | README, 입력, 결정, CURRENT, 인계와 보고서 보존 |

보고서는 생성된 임시 폴더의 docs/reports에 남기고 폴더 경로와 요약을 출력한다.
PASS는 합성 흐름의 실행 결과다. 모델의 문제 해결 능력, 실제 8세션 동시 운영, 감독 연결, 실제 제출은 NOT_RUN이다.

## 실제 과제에서 동일하게 확인할 것

설치와 preflight 이후부터는 과제 README, 실제 답변, 실제 코드와 테스트로 바꿔 진행한다.
합성 질문의 처리 규칙이나 예시 수치를 실제 과제에 적용하지 않는다.
결과를 내는 명령, 검증하는 명령, 실패를 잡는 기준을 각각 남긴다.
플랫폼에서만 가능한 감독과 Browser, 모델 선택, 제출 화면은 응시자가 직접 확인한다.

문답 원문과 동시 저장, 가변 준비 시각, 재설치 보존은 `python3 -m unittest discover -s tests -v`로 확인한다. 실제 AI의 문항 생성 품질은 이 검사만으로 확인되지 않는다.
