# 세션 간 문서 공유

같은 프로젝트 루트를 사용하는 여러 세션이 파일을 읽고 쓰는 방식이다. 세션 실행, 알림, 동기화, 파일 잠금을 자동 제공하지 않는다.
사용자가 연 세션만 참여하며 각 세션은 공식 규칙과 승인된 작업 범위를 따른다.
원본의 메인 → TASK_SPEC → 구현 → SUB_RESULT → 메인 검토 흐름을 유지한다.
S1~S7의 7개 역할을 기본으로 준비하며, 필요 없는 역할은 대기한다.
세션의 역할과 시작 요청은 하네스의 docs/TEAM_PLAYBOOK.md를 참고한다. 설치된 과제에서는 .probe-kit/docs/TEAM_PLAYBOOK.md다. 코드 파일뿐 아니라 공유 서버, 포트, DB와 무거운 검증의 실행 담당도 CURRENT에 배정한다.

## 읽는 순서

1. 프로젝트의 공식 지침과 설치된 경우 `.probe-kit/AGENTS.override.md`, `.probe-kit/docs/RULES.md`.
2. 프로젝트 루트의 [CURRENT.md](CURRENT.md): 목표, 남은 시간, 통합 담당자, 세션 배정, 현재 원장 경로.
3. 자신에게 지정된 `sessions/<session-id>/TASK_SPEC.md`, 기존 SUB_RESULT.md와 HANDOFF.md, 수신 요청의 파일.
4. 해당 작업의 보고서와 근거만 읽고 현재 파일 상태를 확인한다.

문서의 기준 커밋과 현재 HEAD, 미커밋 변경을 비교한다. 커밋이 같아도 작업 폴더의 파일은 달라질 수 있다.
`git status --short`, 필요한 파일의 `git diff -- <path>`로 실제 상태를 확인하며 다른 세션의 변경을 원복하지 않는다.

## 작성 범위와 배정

- 통합 담당 세션 하나가 CURRENT와 공통 REQUIREMENTS, QUESTION_LOG, DECISIONS, EVIDENCE를 관리한다.
- 작업을 시작하기 전에 통합 담당자가 세션 ID, 쓰기 가능한 경로, 완료 조건을 CURRENT에 등록한다. 다른 세션은 등록 전 읽기와 제안만 한다.
- 메인은 `sessions/<session-id>/TASK_SPEC.md`에 원본과 같은 작업 명세를 작성한다. 작업 ID, 목표, 허용 경로, 요구와 제약, 검증, 완료 조건을 담는다.
- 작업자는 같은 폴더의 `SUB_RESULT.md`에 작업 ID, 실제 변경과 검증, 실패와 한계를 기록한다. [TEMPLATE.md](TEMPLATE.md)는 자신의 `HANDOFF.md`로 복사해 인계에 쓴다.
- 여러 작업 세션은 하나의 TASK_SPEC.md 또는 SUB_RESULT.md를 함께 수정하지 않는다. ID는 worker-a, worker-b처럼 현재 작업에서 겹치지 않게 정한다.
- 메인은 진행 중인 명세를 작업자에게 알리지 않고 바꾸지 않는다. 이전 결과를 확인하고 필요한 증거를 보고서에 보존한 뒤 다음 작업 ID를 발행한다. 결과의 작업 ID가 다르면 현재 완료로 처리하지 않는다.
- 공유 원장에 반영할 내용은 세션 문서나 메시지로 제안하고 통합 담당자가 근거를 확인한 뒤 반영한다.
- S7 같은 기록 담당도 자기 WORKLOG와 RECORD_PROPOSALS에 근거를 모아 제안한다. 통합 담당자의 공통 원장을 동시에 수정하지 않는다. 제출 문서를 배정받았다면 해당 파일은 기록 담당자가 독점 편집하고 통합 담당자는 검토 의견을 전달한다.
- S6 같은 검토 담당은 확인된 결함과 의심을 구분하고 재현 근거, 영향, 최소 수정 방향을 보고한다. 제품 코드 수정은 원래 소유자에게 맡긴다.
- 소유 경로가 겹치면 통합 담당자가 범위를 다시 나누거나 앞 작업이 인계될 때까지 그 파일의 편집을 보류한다.
- 파일 소유권은 합의에 따른 운영 규칙이다. 기술적인 잠금이나 자동 충돌 방지는 아니다.

CURRENT의 세션 상태는 PLANNED / ACTIVE / WAITING / HANDOFF / CLOSED로 기록한다.
실행 상태 자동 감지가 아니므로 마지막 갱신 시각을 함께 적는다. 오래된 ACTIVE만 보고 파일 소유권을 임의로 가져오지 않는다.
종료된 세션의 범위 인수는 사용자 또는 현재 통합 담당자가 확인하고 기록한다.

기본 세션 ID는 S1-main, S2-worker-a, S3-worker-b, S4-data, S5-research, S6-review, S7-records다. 설치기는 각 폴더에 빈 TASK_SPEC, SUB_RESULT, HANDOFF를 준비한다. PLANNED는 배정 준비 상태이며 실행 중이라는 뜻이 아니다. 세부 역할은 TEAM_PLAYBOOK 한 곳에서 관리한다.

다른 작업의 결과에 의존하면 먼저 완료된 결과를 읽는다. 단일 작업자도 같은 세션별 경로를 사용한다.
기존 `sessions/<session-id>.md` 기록은 인계 자료로 보존한다. 새 작업은 폴더 구조를 사용한다.

## 요청과 답변

작은 전달은 자신의 세션 문서에 기록하고 파일 경로를 알려준다. 별도 요청이 필요하면 [messages 안내](messages/README.md)를 따른다.
수신자는 요청을 읽고 자신의 파일에 수신 사실과 처리 결과를 남긴다. 다른 세션의 문서를 대신 수정하지 않는다.
문서에 받은 질문, 바뀐 요구, 선택, 코드와 검증을 연결한다. 문서에 쓰지 않은 대화가 공유됐다고 가정하지 않는다.

## 작업 종료와 인계

1. 자신의 세션 문서에 변경 파일, 기준 커밋과 미커밋 변경, 결과, 검증 명령, 미검증, 다음 작업을 적는다.
2. 실행 결과가 길면 `docs/reports/<session-id>-<topic>.md`로 분리하고 링크한다.
3. 상태를 HANDOFF로 바꾸고 통합 담당자에게 경로를 전달한다.
4. 통합 담당자는 실제 변경과 필요한 검증을 확인하고 공통 원장 및 CURRENT를 갱신한다. 인계 수신과 통합 완료를 구분한다.
5. 새 통합 담당자가 CURRENT를 맡으면 이전 담당자는 그 문서와 공통 원장을 더 이상 수정하지 않는다.

실패한 검증은 FAIL, 실행하지 않은 것은 NOT_RUN이다. 기존 결과는 관련 코드나 입력이 바뀌면 재확인이 필요하다.
단일 세션의 짧은 작업은 이 절차를 축약해 CURRENT와 자신의 인계 문서만 사용해도 된다.

## 공유 범위

같은 폴더에서는 저장된 파일이 공유되지만 다른 clone이나 worktree에는 자동 반영되지 않는다.
준비 작업에서는 사용자에게 허용된 경로로 인계할 수 있다. 실제 응시에서는 허용된 같은 과제 환경 안에서만 공유하고 Git push나 외부 전송을 하지 않는다.
기존 `.probe-kit/runtime/HANDOFF.md`는 새 CURRENT를 가리키는 연결 문서로 쓸 수 있다. 과거 원본 handoff 스크립트는 이 다중 세션 구조를 갱신하지 않으므로 동시에 실행하지 않는다.
