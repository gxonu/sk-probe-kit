# 7개 세션 운영과 시작 요청

공통 규칙은 [AGENTS](../AGENTS.md), 사람의 진행 순서는 [foruser](../foruser.md)를 따른다. 세션은 사용자가 같은 과제 폴더에서 직접 연다. 이 문서는 역할 배정 때 필요한 부분만 읽는다.

## 기본 역할

| 세션 | 맡는 일 | 쓰는 곳 |
|---|---|---|
| S1-main | 요구, 방법 선택 합의, 계약과 우선순위, 결과 확인 및 통합 | CURRENT, 공통 원장 4개, 작업자 TASK_SPEC |
| S2-worker-a | 개발 A: 핵심 처리/API/저장 등 배정된 기능 | 배정된 코드, 자기 결과/인계 |
| S3-worker-b | 개발 B: 출력/UI/별도 처리 등 독립된 기능 | 배정된 코드, 자기 결과/인계 |
| S4-data | 데이터 요약, 기준 후보, 단순 기준안과 알고리즘 비교 | 배정된 데이터 처리/계산 코드와 보고서 |
| S5-research | 질문 하나를 위한 공식 자료/공개 레포 조사, 문의 초안 | 자기 조사 결과/인계 |
| S6-review | 계획의 반례, 독립 검증, 제출 전 예상 문항 | 배정된 검증 코드와 자기 보고서 |
| S7-records | 실제 작업 이력과 증거, 배정된 제출 문서 | 자기 SUB_RESULT/HANDOFF의 근거와 반영안, 배정된 제출 파일 |

서비스가 아니면 S2/S3를 입력 처리와 산출, 계산과 보고 등으로 나눈다. 필요 없는 역할은 대기한다. 6개로 줄이면 S5의 한정 조사를 S1/S4가 맡고 검증과 기록은 유지한다.

## 단계별 협업

| 시점 | 연결 |
|---|---|
| 문제 파악 | S1 목표/제출 규격, S4 작은 데이터 요약, S7 필수 문서, S6 중요한 실패 후보 |
| 기준 확인 | S4 실제 데이터 숫자와 기준 2~3안 -> S1 질문 초안 -> 사용자가 담당자 확인 -> S1 요구/결정 반영 |
| 최초 합의 | 방법, 보장 수준, 품질 지표와 단순 대안을 사용자와 합의. S1이 계약과 소유 파일 배정 |
| 첫 완주 | S2/S3 구현, S4 단순 기준안, S6 독립 검증, S7 실제 근거 수집 |
| 개선 | 같은 입력에서 비교. S5는 구체적 막힘만 조사. 변경된 부분의 검증 갱신 |
| 기능 동결 | S6 필수 실패/제출 조건 확인, 소유자가 최소 수정, S7 실제 실행 문서 확정 |
| 제출 전 연습 | S7이 코드/증거 위치 전달 -> S6가 실제 코드를 읽고 예상 5문항 -> 사용자 답변 -> 근거 피드백 |

2차 질문은 기준이 모호하거나 상충할 때 한다. 답을 기다리며 입출력 뼈대와 원본 보존 등 독립 작업은 진행할 수 있다. 중요한 방법 합의 전에는 그 방법에 묶이는 구현을 시작하지 않는다.

## 충돌 방지와 종료 조건

- 한 파일에 작성자 하나. API/출력 스키마, DB, 의존성/잠금 파일, 공통 설정도 소유자를 정한다.
- S4가 계산 모듈을 맡으면 S2는 연결부를 맡는다. S6는 생성기를 그대로 재사용해 정답이라고 판정하지 않는다.
- 공유 서버, 포트, DB, 출력 경로와 무거운 명령의 관리자를 CURRENT에 적는다. 검증은 별도 입력/임시 DB/출력에서 하고 공유 상태를 임의로 초기화하지 않는다.
- S6는 요구/코드 위치, 재현 입력과 명령, 기대/관찰 결과, 영향, 최소 수정 제안을 남긴다. 재현하지 못한 우려는 의심으로 표시한다. 코드 수정은 소유자에게 전달한다.
- S7은 공통 원장 전체를 복제하지 않고 필요한 근거와 반영안을 S1에 전달한다. S1은 중요한 원출력과 코드를 직접 확인한다.
- S5는 질문 하나와 시간 예산을 받아 출처 최대 3개, 적용 범위와 단순 대안을 보고한다. 예산 안에 못 찾으면 미확인으로 종료한다.
- 개선은 필수 조건을 통과한 기준안과 같은 입력으로 비교한다. 시간이 부족하면 작동하는 기준안과 한계를 남긴다.
- 결과 전달은 상태, 변경, 검증, 요청을 짧게 쓰고 파일 경로를 알려준다. 파일 저장은 자동 알림이 아니다.

## 시작 프롬프트

S1은 foruser의 시작 요청을 사용한다. 나머지 세션은 ID를 바꿔 아래 요청 하나로 시작한다.

```text
[S4-data: 실제 세션 ID로 변경]
.probe-kit/AGENTS.md, docs/handoff/CURRENT.md와
docs/handoff/sessions/[내 ID]/TASK_SPEC.md를 읽어.
배정된 역할, 쓰기 파일과 실행 자원을 확인하고 그 범위에서 진행해.
작업 ID, 실제 변경, 명령/출력과 한계는 자기 SUB_RESULT.md에,
현재 상태와 다음 행동은 HANDOFF.md에 남겨.
결과를 바꾼 AI 제안의 수용/수정/폐기와 근거도 기록해.
공통 원장 변경은 S1에 제안하고 완료 시 결과 경로를 알려줘.
```

기록 작성과 실제 테스트 통과는 다르다. 빈 TASK_SPEC은 작업 배정이 아니며 CURRENT와 명세에 실제 범위가 있어야 시작한다.
