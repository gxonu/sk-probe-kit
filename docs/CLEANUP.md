# 설치와 문서 정리 기준

원본 보존과 당일 실행 지침을 분리한다. 저장소의 원본 125개와 해시는 유지하고, 기본 설치에는 실제로 사용하는 통합 프로토콜만 넣는다.

## 당일 읽는 경로

- 사람: foruser의 단계별 실행 순서.
- AI: 공식 과제 지침 -> 통합 AGENTS -> CURRENT와 자기 TASK_SPEC.
- 역할 배정: TEAM_PLAYBOOK. 질문이나 유형 점검은 필요할 때만 읽는다.
- 설명 연습: prompts/mock_exam_5 하나에 절차, 5문항/6축 점검, 피드백과 가상 few-shot을 모았다.

## 통합한 충돌

- 활성 AGENTS/SUB_AGENTS를 같은 프로토콜로 맞췄다. 원본의 메인 코드 읽기 금지와 구형 공용 명세/로그 호출을 제거했다.
- 모델과 추론 수준, 과거 시각과 문항 수를 강제하지 않는다. 실제 안내와 CURRENT의 값을 사용한다.
- Case 안내는 업무별 점검만 남긴다. 공통 기록은 원장 4개와 세션별 결과/인계로 통일했다.
- 테스트 성공을 미리 적은 SUBMISSION_REPORT와 중복 인계 양식은 활성 경로에서 제거했다. 실제 README가 요구한 제출 문서를 실제 근거로 작성한다.
- 데이터 숫자로 기준을 재확인하고 중요한 방법을 합의하며, 생성과 독립 검증을 나누고 AI 제안 처리 근거를 기존 기록에 넣는다.

## 기본 설치 범위

scripts/install.py의 CORE_FILES와 LEDGERS가 명시적인 설치 목록이다. 개발 기록, upstream 원본, 원본 서술형, 도구 조사, 사전 체험과 합성 점검 자료를 기본 복사하지 않는다.
knowledge 94개 파일과 검색 도구는 --with-knowledge로 선택한다. 자료는 공개 저장소 안에 계속 보존한다.
활성 경로에서 제거한 중복 자료는 upstream 원본 또는 Git 이력에 있다. 출처와 라이선스를 삭제하지 않는다.

## 기록 보존

새 설치는 7개 PLANNED 세션과 빈 명세/결과/인계를 생성한다. 실제 역할/파일 배정은 S1이 한다.
기존 과제 파일과 기록을 보존하고 내용 충돌은 쓰기 전에 중단한다. 이전 설치본을 자동 삭제하거나 작업 중인 과제의 기록을 이동하지 않는다.

## 확인한 규모와 검증

빈 과제 폴더 기준 기본 설치 227개에서 63개로 줄었다. --with-knowledge를 선택하면 159개다. foruser는 647행에서 162행으로 정리했으며 복사할 명령, 단계별 요청과 완료 기준을 유지한다.
테스트 22개, 합성 전체 흐름, 원본 해시 125개, 설치 후 상대 링크와 변경 스킬 형식을 확인했다. 실제 7개 AI 세션과 플랫폼 제출은 수행하지 않았다.
