# 공식 규칙과 운영 원칙

## 우선순위와 출처

운영팀의 최신 공식 안내와 응시 화면 → 실제 과제 README/제출 규격 → 사용자 합의 → 키트/공개 후기 순서다. 업무 담당자 답변을 감독 규칙 완화로 해석하지 않는다.
아래 최신 안내는 2026-11-04 재응시 접속 링크 및 사전 준비 안내 메일을 직접 확인해 정리했다. 개인 링크, 원본 메일, 문제와 답안은 공개 레포에 넣지 않는다.

## 11월 4일 최신 메일

- 18:40까지 접속해 준비하고 19:00에 별도 공지 없이 시작한다. 늦게 시작해도 후속 서술형을 포함한 모든 절차는 23:00에 끝난다.
- 사전 체험은 시작 전 1회 15분이며 추가 기회가 없다. 최신 Chrome, 안정적인 인터넷/Wi-Fi, 충전 중인 노트북/휴대폰, 실물 신분증과 독립된 응시 공간을 준비한다. iOS 최신화, Android 감독 앱 재설치는 공식 안내 경로를 따른다.
- 화면은 하나만 사용한다. 무선 키보드와 마우스는 사용 불가이며 노트북 내장 키보드와 트랙패드는 가능하다.
- Codex 사용 가능, Claude와 Astra 사용 불가. 권장 표기는 Sol 6.1, Sol 6.0, Terra 5.6, Luna 6.0이다. 제공된 Codex 버전은 고정이므로 업데이트하지 않는다. upstream 모델 교체를 공식 모델 제한으로 해석하지 않는다.
- 토큰은 충분한 수준으로 제공되며 AI 사용량과 활용 과정은 평가에 참고될 수 있다. 공개된 수치 한도나 세션 수 제한, 감점 계산식은 이 메일에 없다. 목적에 맞게 필요한 맥락과 작업만 사용한다.
- 공개 저장소의 지침, Skill, 하네스, 템플릿과 코드는 상세 가이드의 허용 범위 안에서 활용한다. 사용 저장소는 2차 예선 결과 통지 전까지 공개 유지한다. 비공개 저장소 사용과 외부 자료로 결과물 전체 대체는 불가하다.
- 사용 자료, 제출물과 작업 이력은 검토 대상이다. 과제 내용을 공개하거나 외부에 전송하지 않는다.
- RAM은 16GB다. 역할 수와 무거운 실행 수를 구분하고 S1이 서버, DB, 데이터 처리와 검증의 동시 사용을 조정한다.
- 최종 제출 파일의 전체 용량은 10GB 이하다. 제출 버튼 뒤 완료 표시를 직접 확인한다. 제출 또는 후속 질문 이동 실패는 시험 환경의 문의 기능으로 신고한다. 어떤 디렉터리가 산정에서 제외되는지는 추정하지 않는다.
- 경고 자체가 즉시 감점/탈락은 아니다. 감독/화면 공유 오류는 안내대로 복구하고 반복되거나 복구되지 않으면 발생 시각과 증상을 신고한다.
- 화장실은 별도 문의 없이 1회, 최대 10분이며 카메라, 감독 연결과 화면 공유를 유지한다. 복귀 보고는 필요 없다. 자리에서 연결을 유지하며 식음료 섭취가 가능하다.
- 필요한 본인 확인과 감독 절차에 동의하고 녹화를 유지한다. 정당한 사유 없는 중단과 재개 요청 불응은 응시 제한 또는 평가 제외 사유가 될 수 있다. 감독 기록은 해당 목적에 이용되며 2차 결과 발표 후 14일 이내 파기된다고 안내됐다.
- 플랫폼/감독 장애는 문제 신고로 시각과 증상을 접수한다. 확인된 장애의 시간 보정/재응시 여부는 운영 기준에 따르며 자동 보정을 가정하지 않는다. 개인 기기와 통신망 문제는 응시자 책임이다.

## 기존 상세 가이드에서 확인한 범위

근거는 10월 26일 가이드 3종과 10월 29일 안내다. 당일 화면이나 최신 상세 가이드가 다르면 최신 명시 내용을 우선한다.

- 제공 환경 안에서 작업하고 Git push, 문제/파일/결과물 외부 전송, 개인 PC 파일 업로드, 별도 AI와 개인 API 키 사용을 하지 않는다. 외부 브라우저 직접 열기와 Computer Use/브라우저 자동 조작을 사용하지 않는다.
- 플랫폼의 인증, 관리 설정, 연결 프로세스와 감독 설정을 변경하거나 종료하지 않는다.
- 웹 서비스는 요구된 포트와 0.0.0.0 바인딩을 확인하고, 응시자가 내장 Browser에서 직접 조작한다.
- 후속 서술형은 AI와 복사 붙여넣기 없이 직접 답한다. S8 준비도 제출 확정 전에 끝낸다.
- 사용법은 Cofa Helper, 업무 조건은 업무 담당자, 플랫폼 오류는 문제 신고로 구분한다.
- 이전 안내의 과제 최대 180분, 서술형 6문항 각 5분은 오늘 메일에서 재명시되지 않았다. 화면의 실제 제한 시간을 확인한다. plan_time.py의 기본값은 계획용 가정이다.

## 준비 방식과 미확인 정보

8세션 분담과 예상 6문항은 사용자의 준비 방식이며 공식 운영 요구나 실제 출제 보장이 아니다.
코드를 볼 수 있는지, 어떤 파일/대화로 문항을 만드는지, 특정 작업이 몇 문항을 차지하는지와 감점 공식은 확보한 자료로 확정하지 않는다. 후기의 주장을 공식 사실로 쓰지 않는다.
재응시는 새 과제라는 11월 1일 안내를 기준으로 준비한다. 이전 과제의 알고리즘, 데이터와 화면 구성을 새 요구에 강제하지 않는다.

## 작업 원칙

구현을 바꾸는 질문 최대 3개씩 → 사실/가정과 성공 기준 합의 → 작은 입력의 전체 흐름 → 필요한 개선 → 실제 검증과 제출 순서다.
계산은 코드, 완료는 증거로 판단한다. 결정과 AI 제안의 수용/수정/폐기 이유를 기록하며 전체 마감과 과제 제출 시각을 구분한다.
S6는 시작/중간/제출 전 제약을 확인하고 S1이 조정한다. 규칙과 자원 확인을 마지막 한 번에만 몰지 않는다.
