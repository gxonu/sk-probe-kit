# 한 번의 15분 체험

기기, 충전, Wi-Fi, 신분증과 카메라 구도를 먼저 준비한다. 휴대폰 앱의 설치 QR과 응시 연결 QR을 구분한다.
최신 공지에서 허용된 준비물을 확인한다. 종이 메모나 별도 장비가 허용된다고 가정하지 않는다.

| 시간 | 우선 확인 | 실패 시 |
|---|---|---|
| 0~3분 | 감독 연결, README, 작업 폴더, Helper와 담당자 위치 | 연결 문제부터 해결하고 신고 |
| 3~6분 | 공개 저장소 clone, 설치, 새 Codex 세션에서 지침과 스킬 로드 | 스킬 자동 로드가 안 되면 파일 직접 읽기 |
| 6~9분 | 담당자 답변을 에디터로 옮기기, 저장 확인 | 직접 입력 가능한지 확인 |
| 9~12분 | 작은 서버 실행, 0.0.0.0과 실제 포트로 Browser 미리보기 | 승인 대기인지 실행 오류인지 구분 |
| 12~15분 | 체험 종료와 예시 서술형 흐름 | 본시험의 시작과 구분 |

지식 패키지는 설치본에 포함되어 있으므로 별도로 내려받지 않는다. 모델별 벤치마크, 설정 변경, 전체 의존성 설치를 필수로 넣지 않는다.
clone이 안 되면 같은 명령을 계속 반복하지 말고 README를 읽고 합의, 최소 구현, 검증, 결정 기록의 짧은 작업 원칙으로 진행한다.
체험 결과를 밖으로 가져오는 방법이 허용됐다고 가정하지 않는다. 개인 링크, 환경 토큰, 실제 문제를 공개 저장소에 기록하지 않는다.

## 제공된 작업 공간 안에서 기록하기

체험의 과제 루트에서 15분 기록 폴더를 만든다. 로컬 개인 폴더로 내보내는 명령은 아니다.

```bash
mkdir -p docs/preview_15min
python3 .probe-kit/scripts/preflight.py --workspace . > docs/preview_15min/preflight.json
```

설치 후 사용할 수 있는 명령이다. 실패하면 출력과 실제 종료 상태를 함께 확인한다.
Git 저장소라면 `git status --short`와 필요한 파일의 `git diff`도 이 폴더에 기록할 수 있다.
같은 작업 폴더에서 두 번째 세션이 공유 문서를 읽는지 확인하고, 여유가 있으면 세 번째도 별도 ID로 연다.
결과 메모에는 시각, 확인한 항목, 실제 명령과 결과, PASS/FAIL/NOT_RUN, 다음 행동을 남긴다.

화면은 플랫폼의 감독 기록과 별개다. Dots 등 외부 AI의 화면 관찰이나 자동 조작을 체험 기록 방식으로 연결하지 않는다.
별도 수동 녹화나 캡처 허용 여부는 공식 안내만으로 확인되지 않았으므로 Helper에 허용 범위를 확인한다.
