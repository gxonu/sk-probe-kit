# 후속 서술형 6문항 대비 (문항당 5분 ,  AI 금지 ,  복붙 금지)

제출물을 확정하면 **내 작업 기록을 근거로 문항이 생성**된다. 6문항 × 5분 = 30분.
**AI도, 외부 브라우저도, 복사, 붙여넣기도 안 된다. 본인이 직접 타이핑한다.**
이전 문항으로 돌아갈 수 없다. 시간이 끝나면 자동 확정된다.


---

## 답변 골격 (40초 분량, 4문장)

```
사실  → "문제에는 X 라고만 쓰여 있었습니다."
결정  → "그래서 저는 Y 로 정했습니다."
근거  → "Z 때문입니다."            ← 선택의 이유
한계  → "대신 W 인 경우엔 틀립니다."  ← 적용 범위
```

한계와 검증하지 못한 내용은 실제 코드 및 실행 기록과 일치하게 설명한다.

## 세 가지 금지

| 금지 | 대신 |
|---|---|
| 모르는 걸 아는 척 | "그건 확인하지 않았습니다. 확인하려면 A를 보면 됩니다." |
| "테스트했습니다" (근거 없이) | "실제로 실행한 테스트 명령, 결과와 미검증 범위를 말합니다." |
| AI 탓 / 시간 탓 | "제가 X를 안 할 일로 뒀습니다. 이유는 Y입니다." |

## 연습 질문 22개 (실제 출제 예측 아님)

### 의도
1. 이 결과물의 **사용자는 누구고, 어떤 결정을 개선**합니까?
2. 무엇을 **반드시 지켜야 하는 조건**, 무엇을 **점수로 조정할 것**으로 나눴습니까? 왜 그렇게 나눴습니까?
3. 문제에 **명시되지 않은 것 중 무엇을 가정**했습니까? 그 가정이 틀리면 무엇이 깨집니까?
4. **하지 않기로 한 것**은 무엇이고 왜입니까?
5. Codex에게 무엇을 시켰고 무엇을 직접 했습니까? 그 경계를 어떻게 정했습니까?
6. Codex의 출력을 **어디서 신뢰하지 않았습니까?** 어떻게 검증했습니까?
7. 작업을 어떻게 쪼갰습니까? 왜 그 단위였습니까?
8. 중간에 방향을 바꾼 적이 있습니까? 무엇을 보고 바꿨습니까?

### 기술
9. 이 코드가 **실제로 어디서 어떻게 실행**됩니까? 명령 한 줄로 보여주세요.
10. 같은 입력에 **같은 출력**이 나온다는 걸 어떻게 보장합니까? tie-break는 무엇입니까?
11. 예외, 실패 상황에서 어떻게 됩니까? 그게 일어났다는 걸 사용자가 압니까?
12. 비밀정보와 개인정보를 어떻게 다뤘습니까?
13. 데이터가 **10배** 오면 어디가 먼저 무너집니까?
14. 이 구조를 고른 이유는? **더 단순한 대안**은 왜 부족했습니까?
15. 테스트가 실패하는 걸 **직접 본 적**이 있습니까? 어떤 테스트였습니까?

### 인지
16. 이 결과물에서 **가장 약한 부분**은 어디입니까?
17. **어떤 입력에서 틀린 답**을 냅니까? 하나만 구체적으로 말해보세요.
18. 지금 코드에서 **설명 못 하는 줄**이 있습니까?
19. 다시 한다면 무엇을 다르게 하겠습니까?
20. 시간이 2배 있었다면 무엇을 했겠습니까? 왜 그게 우선순위입니까?
21. 이 지표가 **실제 업무 목표**와 어떻게 연결됩니까?
22. 이 결과를 내일 실무에 넣는다면, 무엇을 먼저 확인해야 합니까?

## 미리 문장으로 써 둘 답변 3개

빌드가 끝나면 이 셋은 **문장으로 적어둔다.** 연습 후 자료 없이 본인의 말로 설명한다.

### ① 상충조건 한 문장
> "이 문제의 상충조건은 ___ 와 ___ 였습니다.
> 저는 ___ 를 반드시 지킬 조건으로 두고 ___ 를 점수로 조정했습니다.
> 섞지 않은 이유는, 섞으면 '왜 이 결과가 나왔는지'를 설명할 수 없기 때문입니다."

### ② 가장 위험한 실패 하나
> "___ 인 입력에서 틀립니다.
> 이유는 ___ 이고, .probe-kit/runtime/REQUIREMENTS.md의 '하지 못한 것'에 적어뒀습니다.
> 고치려면 ___ 가 필요한데 시간 안에 안 된다고 판단했습니다."

### ③ Codex를 어디서 믿지 않았나
> "___ 는 Codex에게 맡겼고, ___ 는 직접 했습니다.
> 특히 ___ 는 Codex 출력을 그대로 쓰지 않고 ___ 로 다시 검증했습니다.
> 검증 없이 통과시키면 ___ 같은 문제가 생기기 때문입니다."

## 제출물 확정 전에 마칠 연습

모의 연습 또는 과제 작업 중 제출물 확정 전에만 진행한다. 확정 이후 실제 후속 서술형에서는 AI 코칭을 사용하지 않는다.

1. `.probe-kit/runtime/REQUIREMENTS.md`의 '하지 못한 것'과 `.probe-kit/runtime/DECISIONS.md`의 '실패 지점'을 다시 읽는다
2. 위 22개 중 **내 결과물에 해당하는 것 5개**를 골라 소리 내어 답한다
3. 답하다 막히면 기록 누락인지 이해 부족인지 구분한다. 관련 코드와 실행 결과를 확인하고 작은 입력 하나의 흐름을 직접 따라간다.
4. 자료 없이 동작과 선택 이유를 자기 말로 다시 설명한 뒤 기록한다. 여전히 확인하지 못한 내용은 미확인으로 남긴다.

리허설에서는 실제 구현에 대한 이해와 기록의 정확성을 확인한다.

주요 설계마다 사용자 요구, 더 단순한 대안, 현재 선택의 적용 조건, 재검토 조건을 설명한다.
입력이나 운영 조건 하나를 바꾸면 어떤 결과와 코드가 달라지는지도 확인한다. 이 질문들은 연습 방법이며 실제 출제 예측이 아니다.
검증 기록을 작성한 세션이 달라도 본인이 중요한 동작과 근거를 확인한다.
