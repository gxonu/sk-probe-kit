# 구현 설명 연습

시험 전 연습인지, 아직 제출물 확정 전인지 문맥으로 확인한다. 실제 서술형 문항에는 적용하지 않는다.

## 현재 코드로 예상 5문항

사용자가 5문항 또는 제출 전 20분 연습을 요청하면 `.probe-kit/docs/mock-exam.md`와 `mock-examples.md`를 읽는다. 이 저장소 자체에서는 `docs/`의 같은 파일을 읽는다.
현재 README/규격, 핵심 코드와 존재하는 기록에서 선택, 구조, 구현 범위, 예외 대응, 추가 검증의 다섯 관점으로 P1~P5를 만든다. 과거 시험 기록은 필요 조건이 아니다.
few-shot은 질문의 구체화 방식만 참고하고 예시의 가상 파일/함수, 도구와 조건을 현재 프로젝트에 옮기지 않는다. 질문마다 실제 읽은 파일:행 또는 함수 근거를 붙인다.
코드 기준과 읽은 범위를 짧게 기록하고, 이유와 실행 결과를 추정하지 않는다. 코드와 문서의 차이도 표시한다. 앱 수정이나 새 무거운 테스트를 하지 않고 배정된 보고서만 작성한다.
먼저 다섯 문제와 근거 위치만 제시한다. 사용자가 답한 뒤 피드백하며, 실제 남은 시간에서 제출 점검 여유를 확보한다. 상세 호출문은 `.probe-kit/prompts/mock_exam_5.md`다.

## 한 문항씩 연습

그 밖의 구현 설명 연습은 `.probe-kit/docs/written-prep.md`를 읽고 현재 코드와 기록에 맞는 질문을 한 번에 하나씩 고른다. 시간은 사용자의 남은 시간에 맞춘다.

## 답변 피드백

사용자가 먼저 스스로 답한 뒤 다음을 확인한다.

- 파일, 함수, 입력 조건과 답변의 일치 여부
- 실제 실행하지 않은 검증을 했다고 주장했는지
- 결정 이유, 대안과 남은 한계가 구체적인지
- 업무 요구와 설계의 연결, 더 단순한 대안, 선택의 적용 조건과 재검토 조건

완성 답변을 대신 써주지 않는다. 사실 오류와 확인해야 할 코드 위치를 짚고 사용자가 다시 설명하게 한다.
막히는 경우 기록 누락과 이해 부족을 구분한다. 작은 입력으로 코드 흐름을 확인한 뒤 자료 없이 자기 말로 설명하게 한다.
특정 평가축의 배점, 실제 출제 문항 또는 점수를 추정해 단정하지 않는다.
