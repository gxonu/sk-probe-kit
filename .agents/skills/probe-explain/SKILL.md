# S8 코드 기반 서술형 대비

공식 규칙과 CURRENT에서 아직 제출 확정 전인지 확인한다. 실제 후속 서술형에는 적용하지 않는다. 사용자의 현재 요청이 코드 기반 준비인지 구분하고, 실제 출제나 평가 점수를 보장하지 않는다.
키트 경로는 설치 시 `.probe-kit/`, 이 저장소 자체에서는 루트다. 자세한 호출 예시는 `prompts/mock_exam_6.md`, 질문 구체화 방식은 `docs/mock-examples.md`를 읽는다. 추가 관점이 필요할 때만 `references/written-prep.original.md`의 관련 절을 참고하고 현재 공식 규칙과 실제 코드에 맞춘다.

## 시작과 입력

S8-explain은 README/제출 규격, 작은 파일 목록, 핵심 코드, QUESTION_LOG/DECISIONS/EVIDENCE, S7의 실제 제출 문서와 관련 로그를 필요한 범위만 읽는다. 없는 문서 때문에 멈추거나 존재하지 않는 구현을 가정하지 않는다.
현재 HEAD와 관련 미커밋 변경, 확인 시각, 읽은 파일/함수와 확인하지 못한 부분을 자기 SUB_RESULT에 적는다. S7 요약만 믿지 않고 핵심 경로를 직접 읽는다. 서버와 제품 코드를 수정하거나 새 무거운 테스트를 실행하지 않는다.

## 시점

- 초기 설계 뒤: 설명해야 할 선택과 기록이 부족한 이유를 찾는다.
- 첫 전체 흐름 완성 뒤: 실제 구현으로 6개 축의 문항/답변 초안을 만든다. 구현 전 가정에 기반한 내용은 가정이라고 표시한다.
- CURRENT에 정한 준비 시점: 최신 코드로 전체 세트를 갱신한다. 기본은 제출 예정 40분 전이며 `--explain-lead-minutes` 또는 사용자 요청으로 바꾼다. 짧은 시간에는 핵심 문항을 우선하고 제출 점검 여유를 침범하지 않는다.
- 최종 변경 뒤: 영향을 받은 질문과 답변만 갱신한다. 제출 확정 뒤에는 중단한다. 자동 예약/감시는 아니다.

## 여섯 관점

| 번호 | 관점 | 질문에 포함할 요소 |
|---|---|---|
| P1 | 설계와 선택 | 실제 방식, 업무 이유, 단순 대안, 필수 제약과 품질 목표, 포기한 것 |
| P2 | 데이터 흐름과 책임 | 입력→검증→처리→저장/출력, 모듈 책임, 상태와 역할 경계 |
| P3 | 구현 범위와 재현 | 구현/실행 확인/가정/미구현, 이유, 재현 파일과 명령 |
| P4 | 실패와 복구 | 잘못된 입력/불가능한 조건/반복/동시 변경 중 관련 상황, 기존 결과 영향, 발견/수정/승인/복구 책임 |
| P5 | 위험과 독립 검증 | 가장 약한 지점, 규모/조건 변경의 파급, 구현과 독립된 근거, 다음 검증 |
| P6 | AI 협업 | 실제 작업 하나, 요구를 알게 된 경로, 사람과 AI의 역할, 수용/수정/폐기와 이유, 검증 및 비용/시간 고려 |

6개는 준비의 범위이지 실제 문항 수의 확정이 아니다. 같은 알고리즘만 반복하지 말고 실제 중요한 선택, 데이터, 상태, 검증과 협업을 고르게 다룬다. 서비스가 아니면 저장/화면을 실제 출력과 처리 경계로 바꾼다.

## 출력 모드

기본은 `자료 모드`: 주요 6문항과 각 문항의 보조 질문 2개를 만들고 모두 답변 초안을 작성한다. 사용자가 보조 문항 수를 정하면 따른다. `연습 모드`는 문제만 먼저 제시하고 사용자 답변 뒤 피드백한다. `갱신 모드`는 변경된 근거에 해당하는 부분만 고친다.

각 주요 문항에는 다음을 포함한다.

1. 현재 구현을 구체적으로 짚는 질문과 요구 요소 3~4개.
2. 실제 읽은 파일:행/함수와 Q-ID/R-ID/실행 근거 1~3개.
3. **준비용 답변 초안**: 질문의 요구 요소를 빠짐없이 설명하는 4~6문장 정도. 선택→근거→한계/파급→다음 검증을 필요한 범위에 적용한다.
4. 보조 질문 2개와 각 1~3문장 답변 초안. 경계 입력, 대안, 실패 책임, 조건 변경처럼 본 문항을 더 깊게 확인한다.
5. `[사용자 확인 필요]`, `[NOT_RUN]`, 미구현 등 남은 빈칸과 반드시 이해할 핵심어.

코드에서 확인한 동작은 설명할 수 있지만 선택 이유, 사용자 의도, 실행 성공은 기록 없이 만들어내지 않는다. 이유가 없으면 확인 질문을 쓰고 완성된 사실 문장으로 꾸미지 않는다. 잘못된 전제를 가진 질문이면 실제 구현과의 차이를 먼저 설명한다.
답변 초안은 암기할 정답이나 사용자의 실제 경험 진술이 아니다. 사용자가 자기 말로 설명하고 코드와 맞는지 확인할 준비 자료다. 준비 문답을 QUESTION_LOG의 실제 담당자 문답이나 EVIDENCE의 실행 성공으로 옮기지 않는다.

## 저장과 피드백

배정된 `docs/handoff/sessions/S8-explain/SUB_RESULT.md`에 코드 기준, P1~P6/보조 문항/답변, 빈칸, 사용자 피드백을 모은다. 파일 배정이 없으면 대화에만 출력하고 S1에 소유권을 요청한다.
연습에서는 사용자의 답변이 요구 요소를 모두 다루는지, 실제 코드와 맞는지, 근거 없는 성공 주장이나 이유가 있는지 확인한다. 가장 중요한 오해와 확인할 코드 위치를 짚고 다시 설명하게 한다. 공식 점수나 합격률을 만들지 않는다.
