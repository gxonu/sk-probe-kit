# 선택과 AI 협업 기록

공통 AGENTS와 CURRENT의 작성 범위를 따른다. 매 명령을 기록하지 말고 결과를 바꾸는 선택을 남긴다.
기록할 내용: 관련 Q-ID/R-ID, 선택과 단순한 대안, 업무 영향과 이유, 실제 검증, 약점/파급, 재검토 조건과 다음 검증이다.

- 필수 제약과 개선 지표를 나누고, 단순 기준안과 비교해 복잡한 방법의 필요성을 설명한다. 특정 솔버나 LLM 사용을 기본값으로 넣지 않는다.
- 선택 이유가 기록에 없으면 사용자 확인 필요로 표시한다. 나중에 그럴듯한 이유를 지어내지 않는다.
- AI 협업 선택이면 실제 사람의 요청, AI 제안, 수용/수정/폐기한 부분과 이유, 관련 코드/검증을 남긴다. 모든 제안을 사용자가 직접 선택한 것으로 쓰지 않는다.
- S2~S8은 자기 SUB_RESULT에 반영안을 쓰고 S1이 공통 DECISIONS에 반영한다. S7은 이 근거로 실제 요구된 AI_COLLABORATION을 작성하고 S8은 설명 문항에 활용한다.
- 결정을 바꾸면 이전 판단을 지우지 않고 새 행에 정정과 이유를 남긴다. 실행하지 않은 검증은 NOT_RUN이다.

S1이 공통 원장에 추가할 때:

```bash
python3 .probe-kit/scripts/decision.py --workspace . --requirement R-01 --choice '선택' --alternative '단순 대안' --reason '실제 이유와 업무 영향' --evidence '실행 근거 또는 NOT_RUN' --limit '약점과 다음 검증'
```

설명하기 어려운 핵심 선택은 사용자에게 짧게 설명하고 이해를 확인한다. 공식 배점이나 자동 가점을 단정하지 않는다.
