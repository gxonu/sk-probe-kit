# 오류 재현과 최소 수정

AGENTS와 CURRENT에서 코드/서버/DB 소유권을 확인한다. 제품 결함과 설치/플랫폼 장애를 구분한다.

1. 관련 스택, 직전 변경과 작은 입력으로 실패를 재현한다. 실제 UI 조작은 응시자가 한다.
2. 기대값의 근거를 README, Q-ID 또는 독립된 작은 정답에서 찾는다. 현재 구현 출력을 정답으로 삼지 않는다.
3. 가설 하나와 최소 수정으로 원인을 확인하고 같은 재현 명령 및 관련 회귀만 실행한다. 잘못된 입력, 실패 후 기존 상태, 반복 실행은 실제 요구에 해당할 때 확인한다.
4. SUB_RESULT에 증상, 원인, 변경 파일, 수정 전 실패와 수정 후 결과, 남은 한계를 적는다. S1의 DECISIONS/EVIDENCE 반영과 S7/S8 설명에 필요한 근거를 연결한다.

약 10분 동안 근거가 늘지 않으면 범위 축소나 담당자 확인을 제안한다. 포트 충돌은 소유 프로세스를 확인하고 소유자가 정상 종료하거나 허용 포트를 조정한다. 알 수 없는 프로세스를 종료하지 않는다.
스킬이 안 보이면 파일을 직접 읽게 하고, python이 없으면 python3를 확인한다. 전달 실패는 TASK_SPEC/SUB_RESULT의 실제 경로와 작업 ID부터 확인한다. 세부 대응은 foruser의 트러블슈팅을 따른다.
Codex 설치 오류를 이유로 응시 중 업데이트하거나 전역 설정을 바꾸지 않는다. 감독/연결 문제는 시각과 증상을 기록해 공식 신고 절차를 따른다.
