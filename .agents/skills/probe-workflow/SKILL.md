# 과제 작업 시작

공식 과제 지침, .probe-kit/AGENTS.md, 프로젝트 루트 docs/handoff/CURRENT.md와 자기 TASK_SPEC 순서로 읽는다. 설치되지 않았다면 알려주고 임의의 전역 설정을 만들지 않는다. 사용자용 순서는 .probe-kit/foruser.md에 있다.

1. README/추가 자료/출력 규격과 작은 파일 목록을 확인한다. 실제 시간 값을 plan_time.py에 넣고 CURRENT에 전환 시각을 기록한다.
2. 목표, 데이터의 행/키/단위/시간, 최종 산출물 계약을 파악한다. 큰 데이터는 코드로 요약하고 표본/전체를 구분한다.
3. S1은 REQUIREMENTS에 사실, 가정, 열린 질문, 제외 범위와 검증 가능한 성공 기준을 정리한다. 결과를 바꾸는 질문 최대 3개를 골라 사용자에게 초안을 준다.
4. 기준이 여전히 모호하면 S4의 실제 데이터 숫자로 2~3안을 비교해 담당자 재확인 초안을 만든다. 질문 예산을 두고 답이 없는 가정의 영향과 진행 범위를 사용자와 정한다.
5. 최초 계획에 중요한 방법 선택과 단순 대안, 보장 수준, 품질 지표와 한계를 포함해 사용자와 합의한다. S1이 DECISIONS에 남긴 뒤 그 방법에 의존하는 구현을 배정한다. 승인 범위의 일반 구현 선택은 반복 승인 없이 진행한다.
6. 기본 7역할과 필요 시 축소 방식은 .probe-kit/docs/TEAM_PLAYBOOK.md를 따른다. 공통 파일과 실행 자원도 소유자 하나를 정한다.
7. 세션별 TASK_SPEC -> 작은 구현 -> 실제 검증 -> SUB_RESULT -> S1 확인 순서로 반복한다. S1은 중요한 코드와 원출력을 직접 확인한다. 필요한 유형 점검만 .probe-kit/docs/scenarios.md에서 선택한다.
8. S7은 실제 근거와 원장 반영안, 배정된 제출 문서를 정리한다. 중요한 AI 제안의 수용/수정/폐기는 판단 주체와 근거를 남긴다.
9. 기능 동결 뒤 필수 R-ID와 증거, 저장/제출 형식을 확인한다. 설명 연습은 제출 확정 전에만 한다. 최종 제출은 사용자 담당이다.

원장은 S1만 쓰고 다른 세션은 자기 결과/인계에 변경안을 남긴다. 실제로 하지 않은 검증이나 사용자 판단을 만들어 넣지 않는다.
