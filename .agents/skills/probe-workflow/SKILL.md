# 요구부터 제출까지

설치된 과제에서는 `.probe-kit/AGENTS.md`, `.probe-kit/docs/RULES.md`, `docs/handoff/CURRENT.md`를 읽는다. 키트 자체에서는 `.probe-kit/` 접두사를 뺀다. 실제 과제 경로가 없으면 없는 경로에 기록을 만들지 않는다.

1. 실제 README/규격과 작은 파일 목록을 확인한다. 데이터 입력, 원하는 판단/출력, 필수 제출물과 실제 시간 제한을 구분한다. 큰 데이터는 `data_scan.py`로 작은 표본부터 본다.
2. `docs/scenarios.md`를 키트 기준 경로로 읽어 case를 고르고 선택한 `skills/case*.md`의 실제 지침을 읽는다. 판별 근거, 정확한 파일 경로와 적용할 점검을 CURRENT에 남긴다. 복합이면 구성 단계와 필요한 case 파일 조합을 보고하고, 맞는 유형이 없으면 억지로 분류하지 않는다. 데이터 과제라는 준비 가정을 실제 요구로 대체한다.
3. S1은 REQUIREMENTS에 사실/가정/열린 질문/제외 범위/성공 기준을 적는다. `$probe-interview`로 구현을 바꾸는 질문을 최대 3개 추천하고 원문을 QUESTION_LOG에 남긴다. 최초 계획 합의 전 구현하지 않는다.
4. S1은 TEAM_PLAYBOOK에 따라 S1~S8의 파일, 서버/포트/DB와 무거운 명령을 배정하고 TASK_SPEC을 발행한다. 독립되는 작업만 병행하며 필요한 역할부터 활성화한다.
5. 작은 입력 하나를 최종 출력까지 연결한다. 구현/검증/기록은 각 담당자가 진행하고, 첫 완주 뒤 S8은 현재 코드로 설명 자료 초안을 준비한다. 사용자에게 중요한 알고리즘과 기준 선택을 짧게 설명해 이해를 확인한다.
6. 개선은 측정된 결함과 필수 조건을 기준으로 한다. 결정은 `$probe-decisions`, 오류는 `$probe-debug`, 완료 판단은 `$probe-verify`를 사용한다. S5 조사는 질문 하나와 시간 예산으로 끝낸다.
7. `plan_time.py`로 전체 마감과 과제 제출 예정 시각을 구분해 CURRENT에 기록한다. S8의 준비 시점은 가변 lead로 계산하고, 제출 확정 전에 6문항과 보조 문항/답변을 정리한다. 짧은 시간이면 전체 흐름과 제출 확인을 우선한다.
8. S6의 검증과 제약 확인, S7의 실제 필수 문서, S8의 설명 자료를 S1이 확인한다. 사용자가 제출 버튼과 완료 표시를 확인한다.

공통 원장은 S1, QUESTION_LOG 추가는 전용 도구, 나머지는 소유 파일만 수정한다. 실전 절차와 복사할 요청은 foruser를 읽는다. 세션 교체 때 HANDOFF를 작성하고 실제 결과와 NOT_RUN을 구분한다.
