# 현재 코드 기반 예상 서술형 5문항

제출 확정 전 약 20분에 사용한다. 자동 실행이나 예약이 아니다. 절차는 설치된 `.probe-kit/docs/mock-exam.md`, 예시는 `.probe-kit/docs/mock-examples.md`에 있다.

```text
$probe-explain
지금은 제출 확정 전이고 남은 시간은 [실제 분]분이야.
현재 과제의 코드와 존재하는 작업 기록으로 예상 서술형 5문항을 만들어 줘.
.probe-kit/docs/mock-exam.md와 mock-examples.md를 읽고 아래 방식으로 진행해.

먼저 실제 README/제출 규격과 작은 파일 목록으로 핵심 실행 경로를 찾아.
HOW_TO_RUN, AI_COLLABORATION, 결정/검증 문서와 실제 코드, 관련 테스트/로그를
존재하는 범위에서 읽고 없는 자료 때문에 멈추지 마.
큰 데이터/로그 전체를 읽거나 앱 코드/설정을 바꾸지 마.
이번 출제 단계에서 무거운 테스트를 새로 실행하지 마.

현재 작업 트리와 읽은 범위를 짧게 기록해.
코드 존재, 테스트 작성, 실제 실행 성공을 구분하고 문서가 코드와 다르면 표시해.
예시의 가상 경로나 구현, 알고리즘을 현재 프로젝트 사실로 복사하지 마.

P1 선택 이유/대안/한계, P2 입력부터 출력과 책임 분리,
P3 실제 구현 범위와 제삼자 검증, P4 예외/규모/시간/반복 입력 대응,
P5 조건 변경 위험과 독립 검증에서 각각 한 문항씩 만들어.
서비스가 아니면 같은 관점을 실제 산출물에 맞춰 바꿔.
각 문항은 현재 코드의 선택이나 경계를 구체적으로 짚고
실제로 읽은 파일:행 또는 함수 근거 1~3개를 붙여.
기록에 없는 선택 이유는 내가 설명하도록 물어. 네가 만들어 답하지 마.

먼저 P1~P5 문제와 근거 위치만 보여 줘. 정답과 상세 힌트는 아직 주지 마.
내가 답한 뒤 정확한 부분, 잘못 이해한 부분, 근거 없는 성공 주장,
남은 시간 안에 반드시 확인할 내용 한 가지를 코드 근거로 피드백해.
공식 점수나 실제 출제를 보장하지 마.

문서 저장 범위가 배정됐다면 자기 reports에 새 파일로 결과를 남기고,
범위가 없으면 대화에만 출력해. 기존 원장과 다른 세션의 문서는 수정하지 마.
실제 남은 시간에 맞춰 제출 점검 여유를 확보해.
```
