# 결정 기록

| 시각 | 요구 ID | 선택 | 버린 대안 | 이유 | 검증 근거 | 남은 한계 |
|---|---|---|---|---|---|---|

추정은 추정으로 표시한다. 실제 코드와 다른 문구는 고친다. 설명 연습은 제출물 확정 전에 마친다.

이유에는 업무 영향과 선택이 유효한 조건을 적는다. 남은 한계에는 재검토할 조건도 적는다.
예: 이유 = 확인된 사용자 요구, 선택의 효과, 적용 범위. 한계 = 아직 확인하지 못한 점, 요구나 규모가 바뀌면 다시 볼 선택.
더 단순한 대안을 비교하고 실제로 확인한 근거만 남긴다. AI 제안을 수용하거나 수정한 이유도 해당할 때 기록한다.
여러 세션에서는 통합 담당자만 이 표와 decision.py를 사용한다. 작업 세션은 자기 인계 문서에 결정안을 남긴다.

최초 계획 합의에는 중요한 방법 선택을 포함한다. 기존 열에 방법/단순 대안/보장 수준/실제 품질과 시간 근거/재검토 조건을 적는다. 수치를 측정하지 않았다면 미측정으로 남긴다. AI 제안의 수용/수정/폐기와 판단 주체를 구분한다.
